# Extra groups, in Buildroot's makeusers format (see docs/manual). A line
# whose username is "-" creates only the group.
#
# udev's default rules hand /dev/rtc* to group "clock"; systemd's own
# sysusers would create it at boot, but that needs a writable /etc, which
# the live ISO does not have. Without it udevd logs "Unknown group 'clock'"
# on every boot and the device stays root-only.
-	-1	clock	-1	*	-	-	-	Real-time clock access

# The demo account, and the owner of the graphical session: ade.service
# runs the compositor as this user (through the drop-in in
# rootfs-overlay/etc/systemd/system/ade.service.d, which overrides the
# unit's own "ade" service account) with PAMName=login, so logind opens a
# session on seat0 for it and hands over the DRM and input fds. The
# terminal the session opens is therefore this user's shell in this user's
# home, and sudo asks this user's password.
#
# A member of wheel, which is what both sudo (10-aos-wheel) and polkit's
# default rules treat as administrators. It has NO password: the field is
# locked (an image carrying a known password was the first thing a
# reviewer would flag), and the live session's sudo asks for none
# (sudoers.d/20-aos-live), because whoever sits at a live stick owns the
# machine anyway; there is no lock screen on the live system for the same
# reason. aos-install deletes this account, the sudoers line and the
# marker, and creates the real account in their place.
#
# Also in "pipewire": that group's entry in /etc/security/limits.d gives the
# session real-time priority for audio through pam_limits, the way PipeWire
# does it on a system without RTKit (Buildroot has none).
admin	1000	admin	1000	!x	/home/admin	/bin/bash	wheel,pipewire,video	Live session account

# greetd runs the greeter -- a compositor with ade-greeter -- as this
# account, in a logind session of its own, so the display and the input
# devices come from logind; no groups needed.
greeter	-1	greeter	-1	!	/var/lib/greeter	/bin/false	-	The login screen's account
